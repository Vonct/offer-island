# Supabase 在线同步候选版

已部署到原 Netlify 站点。默认本地使用，云同步由用户主动登录开启。

## 一次性初始化

1. 打开 https://supabase.com/dashboard/project/etffjouqppkabtsnvxzp/sql/new 。
2. 复制 `supabase/setup.sql` 全部内容并执行。它创建按用户隔离的工作区表及原子版本检查函数，不会上传本地记录。
3. 在 Authentication → URL Configuration 中将 Site URL 设置为实际 Netlify 工作台网址。注册确认邮件使用该地址；验证完成后回原页面用邮箱密码登录。当前未实现密码找回。
4. 打开本地工作台，先导出旧数据；点“登录云同步”注册并完成邮箱验证。App 小岛和外部浏览器分别登录同一账号。它们不会自动共享会话。
5. 登录后通过原导入收件箱预览、去重并确认导入旧备份，再验证两端同步。

公开项目 URL / Publishable key 位于 `web/core/cloud-config.mjs`，它们不具有建表权限。不要将数据库密码、secret 或 service_role 写入客户端。

## 当前行为与限制

- 未登录：桌面使用本地 SQLite；在线网页使用当前浏览器 localStorage，可直接编辑。没有保存的登录会话时不初始化 Supabase SDK、不发起云端请求。示例模式保持隔离。
- 浏览器本地记录只属于当前浏览器和站点，清理网站数据会移除它们，请使用“导出全部”备份。
- 已登录用户保持云同步；账号中可预览本机数据，确认后仅新增到云端，不覆盖已有记录。退出云同步回到原本地记录，云端数据不会自动下载到本地。
- 已登录：以账号云端数据为准；约 3 秒轮询，保存时原子检查 revision，冲突要求重新编辑。
- 用户 ID 来自 Supabase Auth；RLS 限制只能读写自己的工作区。SQL 测试覆盖匿名访问、账号隔离、所有者不可变和旧版本写入拒绝。
- 断网时暂停云端保存，暂未实现离线队列。云端数据不复制到本地 SQLite，因此 MCP 当前仍只操作原本地数据库，尚未连接账号数据。
- 原本地数据不会自动上传或删除。退出账号会回到原本地模式；不在公共机器使用持久登录。
- 这是一份每账号一个 JSON 工作区的首版实现，保留现有共享模型、历史和撤销。不是按记录增量同步。
- 发布前必须移除个人部署内的真实 seed 数据；仅上线 `web/`，登录后从数据库读取账号数据。

## 构建与验证

依赖固定版本，`npm ci && npm run build:cloud` 重建随应用分发的浏览器 SDK；`npm test` 包含 PGlite 上运行的真实 Postgres RLS/事务测试。`npm run build:mac` 构建桌面候选版。

本地 SQL 测试不能替代 Supabase 生产项目验证；仍需完成真实邮箱注册、确认、两端读写、冲突与退出账号验证。管理插件不可用时，将 `setup.sql` 手动运行于 SQL Editor。

## 邀请注册
新注册必须携带 options.data.invite_code；supabase/invitations.sql 在 auth.users 插入前校验私有表中的 SHA-256 哈希并扣减次数。既有账号登录不需要邀请码，本地使用不需要账号。邀请码默认一次有效、90天到期，管理员可在私有表将 remaining 设为0撤销。不要将邀请码明文提交仓库或发布到网页。
