# 图片导入与识别

所有网页入口的「导入收件箱」均支持粘贴（⌘V / Ctrl+V）或选择 PNG、JPEG、WebP。先预览，点击「开始识别」，AI 自动填写投递表单，用户可修改后点击确认保存；本机 OCR 提取文字后再整理。不会自动保存，也不会因切换识别方式而切换数据工作区。

- 未登录：默认本机识别。macOS 本地服务有 Vision 时优先使用，否则使用 Tesseract.js 的独立后台线程。一次一张，最大 8MB / 1200 万像素，可取消；闲置一分钟释放识别线程。
- 登录：默认 AI 识别，可随时切回本机识别。点击开始前提示图片发送至 AI 服务。失败不会悄悄更换处理方式或自动重试收费请求。
- 首次浏览器识别按需从本站加载中英文模型并缓存；打开普通页面不会下载 OCR 引擎或模型。桌面安装包包含这些资源。本机识别精度取决于字体、分辨率、布局，尤其要核对公司名和日期。
- 取消云端识别停止客户端等待，已经到达 DeepSeek 的请求可能仍执行和计费；取消本机浏览器识别终止 worker。

## 云端部署

1. 在 Supabase SQL Editor 执行 `supabase/ocr-quota.sql`。配额表仅服务端可访问，所有客户角色不能调用扣减函数。每账号 UTC 每日最多 30 次，最短间隔 5 秒；上游失败也占一次请求额度以限制重试。
2. 部署 `supabase/functions/offer-ocr`，保留 JWT 校验。函数还会通过 Auth 服务验证用户，拒绝匿名或未确认邮箱的账号，不依赖用户可编辑的 metadata 判断权限。
3. 在 Edge Functions Secrets 设置 `DEEPSEEK_API_KEY`。不要写到 cloud-config.mjs、网页、浏览器存储或 Git。可选 `DEEPSEEK_OCR_MODEL`，默认 `deepseek-flash`（2026-09-10 官方 API 的 V4.1 Flash 名称）。
4. 自部署站点设置 `OCR_ALLOWED_ORIGINS`，用逗号分隔准确 Origin。默认官方 Netlify 与 localhost / 127.0.0.1 的 8780、18783 端口。

函数通过单次 Chat Completions 请求输出结构化 JSON（公司、职位、JD、状态、日期、链接、备注、下一步、原文及待确认提示），后端与前端均校验字段，丢弃模型提供的身份字段；自动填表并展示已填写字段，用户点击确认保存后才写入。没有 Agent 循环。底层提供方为 DeepSeek，Key 仅在服务器端使用。函数，没有 Agent 工具权限，不读投递记录、不将图片写入数据库或 Storage、不记录图片和 API Key。用户核对后由原有导入流程写入当前工作区。第三方模型对输入的处理遵循其服务条款。

浏览器资源已随源码提交；升级 OCR 依赖后执行 `npm run build:ocr`，一并提交 vendor 资源与锁文件。Netlify 仍只发布 `web/`。
